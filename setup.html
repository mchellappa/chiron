Setup Guide

Everything you need installed and configured before your first Dojo session.

FDE Dojo / Setup Guide

1Install OpenCode

OpenCode is the agent runtime Chiron runs on. Pick the method for your OS.

macOS / Linux (quick install)

curl -fsSL https://opencode.ai/v2/install | bash

macOS / Linux (Homebrew, recommended)

brew install anomalyco/tap/opencode-v2

Any OS (Node package managers)

npm i -g @opencode/cli@latest # or: bun / pnpm / yarn

Windows (desktop app)

Download opencode-desktop-win-x64.exe from opencode.ai/download (beta).

If you already have an older OpenCode install, remove versions prior to 0.1.x first to avoid conflicts.

The install script places OpenCode at $HOME/.opencode/bin. Verify it worked by opening a new terminal and running:

opencode --version
Verify

Install commands are version-sensitive and change over time. This reflects the install instructions published at github.com/anomalyco/opencode as of this writing - if something doesn't match, check that page directly.

2Get Chiron onto your machine

A plain OpenCode install is a generic coding agent. This step gives it the Chiron persona - the one that gauges your understanding, runs the Socratic loop, and knows the FDE Dojo curriculum.

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/mchellappa/chiron/main/scripts/install-chiron.sh -o install-chiron.sh bash install-chiron.sh

Windows (PowerShell)

iwr https://raw.githubusercontent.com/mchellappa/chiron/main/scripts/install-chiron.ps1 -OutFile install-chiron.ps1 .\install-chiron.ps1

By default this creates a folder at ~/fde-dojo (or $HOME\fde-dojo on Windows) containing an AGENTS.md file - OpenCode automatically loads this as local instructions whenever you run it from inside that folder. This is deliberately project-scoped: it does not touch or overwrite any global OpenCode configuration you already have.

Want a different install location? Pass it as an argument: bash install-chiron.sh /path/you/want (macOS/Linux) or .\install-chiron.ps1 -TargetDir "C:\path\you\want" (Windows).

Confirm it worked:

cd ~/fde-dojo # or your chosen folder opencode

If Chiron greets you as "the educator running the FDE Dojo" instead of a generic assistant, it worked.

Verify

How OpenCode loads local AGENTS.md files, and whether a newer OpenCode version changes this mechanism, is worth confirming against opencode.ai/docs if this step doesn't behave as described.

3Get model provider access

OpenCode needs an LLM behind it. Choose one option and configure it before your first session.

Option A

GitHub Copilot (simplest for individuals)

  1. Confirm you have an active GitHub Copilot license (Individual, Business, or Enterprise) through your GitHub account.
  2. In OpenCode, run the authentication flow for the Copilot provider - typically opencode auth login and select GitHub Copilot when prompted, or follow the provider setup in OpenCode's docs at opencode.ai/docs.
  3. Confirm the model is reachable by starting OpenCode and sending a test message.
Option B

Azure AI Foundry endpoint (if your organization provides one)

  1. Get the Foundry project endpoint URL and a deployed model name from your program admin (e.g. the squad's existing Foundry deployment).
  2. Get an API key or confirm you have RBAC access (e.g. Cognitive Services OpenAI User) for that project.
  3. Configure OpenCode to point at that endpoint instead of Copilot - see OpenCode's provider configuration docs for the exact config keys, since this is specific to your OpenCode version.
Verify

Exact provider configuration commands/config file keys change between OpenCode versions - confirm against opencode.ai/docs or ask your program admin for a working config to copy.

4Get sandbox access

A scratch JIRA project and a scratch GitHub repo - never your company's real ones.

Sandbox JIRA

  1. If your program admin provides a shared sandbox JIRA project, get invited to it and confirm you can create/transition tickets.
  2. If setting up your own: sign up for a free Atlassian Cloud trial at atlassian.com/software/jira/free, create a new project, and note its project key (e.g. SANDBOX).

Sandbox GitHub repo

  1. If your program admin provides a shared sandbox repo, get added as a collaborator.
  2. If setting up your own: create a new (private is fine) repository on your personal GitHub account dedicated to Dojo exercises - do not reuse a real project repo.

Before your first session, confirm you have:

  • OpenCode installed and running (opencode --version works)
  • Chiron's AGENTS.md in your chosen project folder
  • A model provider configured and responding to a test message
  • A sandbox JIRA project key you can create tickets in
  • A sandbox GitHub repo you can branch and open PRs against

Ready to start

Open OpenCode and say:

Chiron, I'm starting the FDE Dojo, Track A Unit 0.

If something above didn't work, tell Chiron what failed (the exact error, if any) rather than guessing past it - getting the environment right matters before the curriculum starts.
