FDE Dojo

Run by ChironSandbox only

Welcome. The FDE Dojo trains experienced engineers to operate as Forward Deployed Engineers inside an Agentic SDLC pipeline: owning a piece of work end-to-end (requirements, design, build, test, deploy) alongside AI agents, not just waiting for handoffs.

Every exercise here runs in a sandbox - a scratch JIRA project and a scratch GitHub repo that you or your program admin set up. Nothing you do here touches production systems.

Before you start

1. Install OpenCode (or whatever agent runtime your program admin specifies) on your machine.
2. Get access to a model provider. Chiron runs on an LLM - typically a GitHub Copilot license, or an internal Azure AI Foundry endpoint if your organization provides one. Confirm with your program admin which to use before you begin.
3. Get sandbox access. You will need:
  • A scratch JIRA project (not your company's real project)
  • A scratch GitHub repository you can branch and open PRs against
Your program admin provisions these for your cohort.
Do not point any exercise at a real production JIRA project or GitHub repository. The Dojo is a practice space - mistakes here are free; mistakes in production are not.

How it works

The Dojo has two tracks, taken in order:

  • Track A - FDE Fundamentals: the role itself - turning an ambiguous business ask into a problem statement, embedding with stakeholders, and judging the right delivery mechanism. Nothing here is specific to agentic pipelines.
  • Track B - Agentic SDLC Specialization: how to execute once an agentic pipeline is the chosen delivery mechanism - ticket-state discipline, branch/PR traceability, working alongside build/test agents.

You work through each track's units in order. Each unit ends with a scenario exercise. Chiron grades your exercise output against a rubric, tells you your score and gaps, and decides whether you advance or repeat the unit. You can ask Chiron to explain any gap in as much depth as you want - the point is understanding, not just a passing score.

Track A - FDE Fundamentals

Unit A0 - What an FDE actually is

The embedded, outcome-owning archetype, contrasted with a typical feature-team role.

Unit A1 - From business objective to problem statement

Translating an ambiguous ask into a concrete, testable problem statement.

Unit A2 - Stakeholder embedding and trust

Working directly with the business/customer; reading unstated constraints.

Unit A3 - Solution judgment (build vs. buy vs. automate)

Choosing the right delivery mechanism for the problem - an agentic pipeline is one option, not the default.

Unit A4 - Rapid prototyping under ambiguity

Getting to a demonstrable thing fast to de-risk assumptions.

Track B - Agentic SDLC Specialization

Prerequisite: Track A complete.

Unit B0 - Orientation

What an Agentic SDLC is, why the FDE model fits it, and how to read a ticket's full lifecycle.

Unit B1 - The Pipeline

Choreography vs orchestration, label-based state machines, System of Engagement vs System of Execution.

Unit B2 - Requirements and Design

Writing an "agent-ready" ticket; how specs become sub-tasks.

Unit B3 - Build and Handoff

Branch/PR conventions for traceability; working alongside build/test agents.

Unit B4 - Deploy / Change Management

What "done" means in an agentic pipeline; the FDE's role at cutover.

Capstone

One sandboxed scenario, start to finish, across all of Track B.

Starting your first session

Open your agent runtime and say something like:

Chiron, I'm starting the FDE Dojo, Track A Unit 0.

Chiron will gauge what you already know before explaining anything - answer honestly, it shapes how deep the first explanation goes.

Practice sandbox

Unit B1 and Unit B3 have a hands-on practice page: sandbox.html - a mock JIRA ticket board and a mock GitHub branch/PR validator, entirely client-side. Nothing on that page touches a real JIRA project or GitHub repo.

When you're done, click Export my work on that page. It downloads a JSON file recording everything you tried (including mistakes - that's fine, it's a sandbox). Then tell Chiron where the file landed, e.g.:

Chiron, grade my sandbox export at C:\Users\you\Downloads\fde-dojo-sandbox-....json

Chiron reads the actual recorded actions, not just what you report, so feedback is based on what really happened.
