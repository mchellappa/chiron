# Rubric: Unit B3 - Build and Handoff

Core claim: branch/PR naming conventions are the actual mechanism that
lets GitHub activity update ticket state automatically - and the FDE's
verification job (does this solve the business problem) is distinct from
what build/test agents verify (mechanical correctness).

## Pass
- Produces a correctly formatted branch name and PR title for a real
  sub-task (matching `type/KEY-summary` and a PR title referencing the
  key), and used the sandbox to validate it rather than just asserting
  it's correct.
- Correctly divides verification responsibility: names something only a
  human FDE could judge (does this solve the actual problem, is scope
  right) versus something an agent appropriately handles (tests pass,
  code compiles).

**Chiron's action:** Affirm the correct branch/PR formatting and,
specifically, the quality of the human-vs-agent division (this is the
part people most often get backwards). Advance.

## Developing
- Branch/PR naming is close but has one mechanical error (wrong
  separator, missing type prefix, ticket key typo) - caught by the
  sandbox but not yet corrected.
- Divides work between human and agent, but the human side is described
  too narrowly (e.g. "the FDE checks the code style" - that's actually the
  agent's job) or too broadly (claims the FDE should personally verify
  every test).

**Chiron's action:** Do not advance. Point at the specific sandbox
rejection message and have them fix just that error. For the division-of-
labor confusion, ask: "would a pattern-matcher reliably catch this, or
does it need business judgment?" to help them re-sort the list.

## Not Yet
- Branch/PR naming ignores the convention entirely (e.g. `my-fix`,
  generic PR title with no ticket reference).
- Believes the FDE should personally re-verify everything the Test agent
  already checks (test pass/fail), missing the orchestration point from
  Unit A2 applied here - not using the agent's verification as leverage.

**Chiron's action:** Do not advance. Have them open the sandbox live and
try their attempt, read the exact rejection reason, and connect this unit
back to Unit A2's orchestration principle before retrying.
