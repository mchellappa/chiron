# Rubric: Unit B1 - The Pipeline

Core claim: this pipeline uses choreography (agents react to shared
label-state independently) rather than orchestration (central controller)
- and the sandbox demonstrates that invalid transitions are rejected, not
silently allowed.

## Pass
- Correctly identifies the shortest valid path from
  `stage:requirements-ready` to `stage:build-ready` (through running,
  done, design-ready, then build-ready).
- Correctly predicts that a ticket stuck at `stage:design-await` with
  nobody watching simply stays there indefinitely - choreography has no
  built-in escalation unless something (a human or another agent) acts.
- Actually used the sandbox and can describe what the rejection message
  looked like for an invalid transition they tried.

**Chiron's action:** Affirm the correct path and the "stuck ticket" insight
specifically - that insight (choreography has no automatic escalation) is
often the deeper, non-obvious part of this unit. Advance.

## Developing
- Gets the valid path right but didn't actually use the sandbox, or used
  it only for valid transitions without trying an invalid one.
- Understands orchestration vs. choreography as a definition but doesn't
  yet see the practical implication (a stuck ticket needs a human to
  notice; nothing fixes it automatically).

**Chiron's action:** Do not advance. Send them back to the sandbox
specifically to trigger a rejection and report the exact log message
before continuing - this unit is meant to be felt, not just read.

## Not Yet
- States an invalid path as if it were valid, or claims a central poller
  would "catch" and auto-escalate a stuck ticket (misunderstanding the
  "dumb poller" point from the pre-read).
- Cannot distinguish choreography from orchestration even after the
  dance/orchestra analogy is re-explained.

**Chiron's action:** Do not advance. Re-walk the full ticket lifecycle
diagram from Unit B0 and B1 together, then have them attempt the sandbox
exercise live, narrating each click before pressing it.
